# 失败分诊

## 输入

[自动化执行/](../自动化执行/自动化执行.md) 的失败清单与原始输出。

## 三分法（必做归因）

| 类别 | 判据 | 处置 |
|---|---|---|
| 真缺陷 | 断言点确实违反契约/验收标准 | 立缺陷单，交被测方修复 |
| 脆弱用例 | 同代码重跑结果漂移、依赖时序/环境 | 修用例或隔离，登记 flaky |
| 环境抖动 | 依赖不可用、资源不足、配置缺失 | 修环境并重跑，留证据 |

## 步骤

1. **先复跑**：同提交重跑取分布，不凭单次结果定性；
2. **看断言**：定位失败断言与 trace 对应关系，判是否违反验收标准；
3. **归因入链**：`logic_chain.py add --from 失败 --to 类别 --why <证据>`；
4. **定责**：真缺陷归被测代码；flaky 归测试资产；环境归运维配置；
5. **闭环**：修复后回 [自动化执行/](../自动化执行/自动化执行.md) 重跑。

## 禁止（红线）

- 放宽断言、删除用例、加 skip/xfail、调大超时来「修绿」；
- 未复跑即宣称偶发；
- 长期挂 flaky 无去向（flaky 清单须有整改人与期限）。

## 退出

每个失败有类别＋证据＋去向，`process_chain.py save --step 失败分诊`，
进 [质量门禁/](../质量门禁/质量门禁.md)。
