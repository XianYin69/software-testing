# 整体审查

## 九项标准

| # | 项 | 校验方式 |
|---|---|---|
| 1 | 流程闭环 | 创建/修改两条路径每步可达、无断链 |
| 2 | 悬空链接＝0 | `python ../../scripts/check_links.py` |
| 3 | 行数红线 | `python ../../scripts/check_len.py`（每 .md ≤50 行） |
| 4 | 目录规范 | 文件夹名＝流程名；脚本英文名；根文档四件必存；`scripts/*.py` 与清单双向对齐（[ST-003](../../references/编排判例/ST-003-根文档与清单一致性.md)） |
| 5 | 依赖合规 | `deps.json` 每条含 `source_url`（`lint_deps.py`） |
| 6 | 约束完整 | `resistance/` 无删减，只加严 |
| 7 | 越界清晰 | 语言专项/Web E2E/发布链路委派均有去向 |
| 8 | 机制挂钩 | 五机制每步有 save/hit/interrupt 挂点 |
| 9 | 双链辩论 | 审查节点有 pro/con 论据与 verdict 记录 |

## 步骤

1. 逐项跑校验，收集输出（失败即记 `process_chain.py interrupt`）；
2. 缺陷回对应步骤修复后 resume，不在审查步内直接改本体；
3. 全绿后记 `logic_chain.py add --from 审查 --to 通过 --why <证据>`；
4. 重试计数 `penalty.py hit`，达 10 次熔断回退或求助用户。

## 判据

任一项不过＝整体审查不通过，不得进 [收尾/](../收尾/收尾.md)。
