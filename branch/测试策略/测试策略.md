# 测试策略

## 输入

[需求确认/](../需求确认/需求确认.md) 的范围与非范围、[经验查询/](../经验查询/经验查询.md) 的清单。

## 步骤

1. **分层**：单元 / 集成 / 契约 / 端到端 / 回归 / 性能，各层写清「为何需要这层」；
2. **风险排序**：按失效代价 × 变更频率排测试优先级，高风险区加厚、稳定区减薄；
3. **判据映射**：每条验收标准至少对应一类测试，无对应即缺口；
4. **投入预算**：单轮时长上限、可并行度、失败即中断点；
5. **取舍入链**：`logic_chain.py debate` 记录「测到哪层为止」的正反论据。

## 分层原则

- 断言尽早：能在单元层抓住的不推到端到端；
- 端到端只覆盖关键用户旅程，数量受预算约束；
- Web 浏览器旅程不在本层自研，派 webapp-testing 并在策略里写明接口。

## 产出

一页策略：分层表 ＋ 优先级 ＋ 判据映射 ＋ 预算 ＋ 不测清单。

## 禁止

- 只写「要测」不写「凭什么算过」；
- 用覆盖率数字替代风险判断（覆盖率是结果不是目标）。

## 退出

`process_chain.py save --step 测试策略`，进 [用例设计/](../用例设计/用例设计.md)。
