# 约束编写

## 定位

把测试链路中「必须/禁止」类判据写进 `resistance/`，作为兜底与降级依据。

## 步骤

1. **识别**：哪些判据一旦违反即造成错误放行（红线区识别见
   [约束部分](../../resistance/约束部分/约束部分.md)）；
2. **编写**：一条约束一个文件夹，自然语言，四段式（条件/必须/禁止/违反后果），
   ≤50 行；
3. **合并**：与既有约束冲突时取更严者，不做「择一丢弃」；
4. **挂钩**：在对应步骤 md 里写明触发条件与降级动作；
5. **辩论**：`logic_chain.py debate` 记正反双链，再落盘；
6. **入索引**：新条目必须登记进 [resistance.md](../../resistance/resistance.md)。

## 红线

- `resistance/` 既有条目**只可加严，不得放宽或删除**；
- 约束变更须走 [update/update.md](../../update/update.md) 审批流（tmp 镜像 →
  compare → release）；
- 未指定判据来源的约束不入库（避免凭感觉立规）。

## 退出

约束清单与各步骤挂钩完成，`process_chain.py save --step 约束编写`。
