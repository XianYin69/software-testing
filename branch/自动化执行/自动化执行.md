# 自动化执行

## 输入

[用例设计/](../用例设计/用例设计.md) 的用例集与夹具。

## 步骤

1. **落框架**：按被测栈选既有测试框架与运行入口，不引入自研 runner；
2. **环境**：依赖版本、数据准备、外部桩；环境清单写成可复现脚本或配置；
3. **分层跑**：先单元快反馈，再集成/端到端；端到端受预算约束；
4. **记录**：保留真实运行输出（命令、时间、通过/失败计数、报告路径）——
   这是 [测试门禁](../../resistance/测试门禁/测试门禁.md) 要求的证据四件套来源；
5. **CI 挂点**：写明触发时机与失败即中断点，交付给发布链路。

## 越界处置

去向权威清单：[委托边界](../../resistance/委托边界/委托边界.md)。

| 情况 | 去向 |
|---|---|
| 需写/改被测代码 | 派 general-programming / python-expert / cpp-expert |
| 浏览器用户旅程自动化 | 派 webapp-testing |
| 数据库夹具与迁移 | 派 database-management |

## 禁止

- 只在本地「手动跑一次绿」就当作可复跑资产；
- 用睡眠等待替代显式条件等待（引入 flaky）；
- 把 `test-results/`、缓存、虚拟环境写进 skill 目录。

## 退出

一轮完整运行记录齐备且可复跑，`process_chain.py save --step 自动化执行`，
进 [失败分诊/](../失败分诊/失败分诊.md)。
