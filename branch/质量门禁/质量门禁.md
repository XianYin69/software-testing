# 质量门禁

## 定位

测试链路的**放行判据**产出点：只回答「凭什么可以放行」，不做发布动作
（发布链路派 packaging-and-release）。

## 门禁项（阻塞级）

| 项 | 判据 | 未过处置 |
|---|---|---|
| 用例全跑 | 本轮计划用例 0 跳过（skip/xfail 须有批准记录） | 中断，回自动化执行 |
| 失败清零 | 真缺陷全部闭环或豁免留痕 | 中断，回失败分诊 |
| flaky 台账 | 漂移用例有类别、证据、去向与期限 | 记降级，限期整改 |
| 判据覆盖 | 每条验收标准至少一条用例可追溯 | 缺口清单，回用例设计 |
| 可复现 | 换干净环境重跑结果一致 | 记环境阻塞 |

约束依据：[测试门禁](../../resistance/测试门禁/测试门禁.md)（证据四件套与三态结论）、
[用例溯源](../../resistance/用例溯源/用例溯源.md)（判据覆盖的双向要求）。

## 步骤

1. 汇总 [失败分诊/](../失败分诊/失败分诊.md) 结论与运行记录；
2. 逐项打分：通过／阻塞／可放行带条件；
3. 写门禁结论（含证据路径、提交号、时间）；
4. `logic_chain.py debate` 记录带条件放行的正反论据，结论留痕；
5. 交付结论给发布侧：[收尾/](../收尾/收尾.md) 或 packaging-and-release。

## 禁止

- 无运行记录给「通过」；
- 以覆盖率达标替代判据覆盖；
- 把阻塞项降级而不留痕（降级须走
  [降级策略](../../resistance/降级策略/降级策略.md)）。

## 退出

门禁结论＝0 阻塞项或条件清单经确认，`process_chain.py save --step 质量门禁`。
