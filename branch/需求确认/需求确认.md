# 需求确认

## 输入

被测变更集、验收标准、已有缺陷单、约束条件（时间窗口/环境/数据）。

## 步骤

1. **区分路径**：新建测试资产走创建路径；纠正已有流程内容走
   [修改流程/](../修改流程/修改流程.md)。
2. **澄清对象**：测什么（模块/接口/用户旅程）、不测什么、判据从哪来。
3. **明确风险**：失效代价 × 变更频率，标出高风险区与不可回归区。
4. **确认资源**：可执行环境、测试数据与账号是否可得，缺即记阻塞项。
5. **留痕**：`logic_chain.py add --from 需求 --to 范围 --why <取舍>`。

## 判据（可测性）

- 每条验收标准须可观测（有输出/状态/断言点），否则回退澄清；
- 无判据的需求不进 [测试策略/](../测试策略/测试策略.md)。

## 越界处置

| 情况 | 去向 |
|---|---|
| 需求文档缺失 | 记阻塞项，向用户一次一问 |
| 需改被测代码才可测 | 派 general-programming / 语言专家 |
| 属 Web 端到端交互验证 | 派 webapp-testing |

## 退出

范围与非范围写定并 `process_chain.py save --step 需求确认`，
进 [经验查询/](../经验查询/经验查询.md)。
