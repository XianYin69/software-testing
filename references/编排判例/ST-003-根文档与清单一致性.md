# ST-003 根文档与脚本清单一致性
- 状态：confirmed ｜ 置信度：0.8 ｜ 记录日期：2026-10-07
- 来源证据：本轮 `git log --oneline`（`129ffa3` 及其前二条）＋`git status`＋目录实盘：
  0.1.3 时根仅有 `SKILL.md`／`CHANGELOG.md`／`LICENSE`／`.gitignore`
  （`README.md`／`CONTRIBUTORS.md` 缺失），同仓 `packaging-and-release`、
  `git-remote-management` 均有 README＋CONTRIBUTORS，仅本技能缺。
## 现象
技能目录结构齐（branch／scripts／references／resistance／dependence／planned_tasks／
update／agent 八区俱在），但**根文档缺件**：安装后无 `README.md` 可读，包管理器与
人审都拿不到「这是什么、怎么跑、边界在哪」的一屏入口；`CONTRIBUTORS.md` 缺失使
贡献规则只散落在 `resistance/` 与 `update/`，无署名口径。
反向风险同型：脚本清单与 `scripts/` 实存文件不符（清单少行或多行），
`scripts.md` 变成悬空索引的镜像问题——链接不悬空但内容不对齐，
`check_links.py` 判不出（它只验指针存在，不验集合相等）。
## 判据
1. 根文档四件必存：`README.md`／`CHANGELOG.md`／`CONTRIBUTORS.md`／`LICENSE`；
2. `scripts/*.py` 的全集 ＝ `scripts/scripts.md` 清单行的全集（双向对齐，
   多一行少一行都算漂移）；
3. 文档间口径不得互斥：README 的上手命令必须与 `scripts.md` 用法约定一致，
   CHANGELOG 条目必须能在实盘找到对应文件；
4. 校验手段限于脚本可判部分（行数／悬空链接／deps），集合对齐须人肉或
   一次性列表比对——**不得口头声称已核**（[测试门禁](../../resistance/测试门禁/测试门禁.md)：无证据不放行）。
## 动作
1. 补齐时走 [update](../../update/update.md)：tmp 镜像写 → compare → release → clean；
2. 迁出历史条目以让位 ≤50 行红线时，**只换承载文件、不改正文**，并在新文件首行注明迁出源；
3. 接线：[收尾](../../branch/收尾/收尾.md) 第 4 步、[整体审查](../../branch/整体审查/整体审查.md) 第 4 项；
4. 同类漂移再现 → 直接引用本判例并按其判据 1–4 逐条给证据。
