# 委托边界

## 条件

任一步骤中的诉求超出测试链路范围（写实现、跑浏览器端到端、发布、远程协作）。

## 必须派发的边界

| 越界诉求 | 派给 |
|---|---|
| 写/改被测代码、重构、修缺陷实现 | general-programming；语言专项 python-expert / cpp-expert / c-expert |
| 浏览器用户旅程端到端 | webapp-testing |
| 发布、打包、版本号、回滚 | packaging-and-release |
| 数据库夹具与迁移 | database-management |
| 并发/性能瓶颈设计 | concurrency-design |
| 总控编排、多领域取舍 | general-software-dev |
| 提 PR／远程协作（push/PR/可见性） | git-remote-management |
| 新领域且无匹配技能 | Skill_Generator（走创建路径） |

## 必须

- 派前先根植判据：**委托的是能力，不是结论**——放行判据、用例与分诊结论留在本技能；
- 派发时给：目标、验收判据、证据要求；收回时只留**链接＋一句话摘要**；
- 判不了归属→问用户一次（ask_user），不擅自自建轮子。

## 禁止

- 空手拒绝（无匹配技能须走 Skill_Generator，不临时拼凑）；
- 在本技能目录复制被派技能的内容或新建重复脚本（伞形不重复）；
- 把派发结果整段正文复述进本体文档或收口。

## 违反后果

职责重叠导致双改冲突、上游更新即失效、审查无法判定归属；测试技能退化为副本仓库。
