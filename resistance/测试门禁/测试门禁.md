# 测试门禁

## 条件

给出「可以放行／可以合入」结论时，即执行
[质量门禁](../../branch/质量门禁/质量门禁.md) 之时。

## 必须

1. **证据四件套**：提交号、运行命令、真实输出（或报告路径）、时间——缺一即不成立；
2. **五阻塞项全核**：用例全跑、失败清零、flaky 台账、判据覆盖、可复现
   （判据见 [质量门禁](../../branch/质量门禁/质量门禁.md) 门禁表）；
3. 结论三态之一：`通过`／`阻塞`／`带条件放行`；带条件必须列条件清单、责任人与期限；
4. 门禁项按风险驱动：失效代价高（数据、资金、安全、对外接口）→ 加严不加宽；
5. 结论落链：`logic_chain.py add --from 门禁 --to <结论> --why <证据>`。

## 禁止

- 无运行记录给「通过」（口头「我本地跑过绿」不算证据）；
- 以覆盖率数字替代判据覆盖，或以「用例数达标」替代失败清零；
- 用 skip／xfail／放宽断言／调大超时把门禁「修绿」；
- 把阻塞项静默降级为条件（降级须走
  [降级策略](../降级策略/降级策略.md) 并告知用户）；
- 越过发布动作：发布派 [packaging-and-release](../委托边界/委托边界.md)。

## 违反后果

缺陷随放行外溢且不可归因；门禁失去可信度后所有历史结论需重跑，成本翻倍。
