# 约束部分（红线区识别）

## 什么算红线区

1. 本目录 `resistance/` 全部内容；
2. `SKILL.md` 的「红线摘要」与「工作原则」；
3. `branch/质量门禁/`、`branch/失败分诊/` 的判定条款（放行与归因标准）；
4. `dependence/deps.json` 的必填字段与 `source_url` 规则；
5. 用例最小字段（`trace`／`expect`）——见
   [用例溯源](../用例溯源/用例溯源.md)。

## 识别规则

- 文本出现「必须／禁止／不得／即判不合格／违反后果」即属约束文本；
- 约束只写在 `resistance/` 与步骤文档的「禁止／红线」小节，不散落他处；
- 每条约束四段式：**条件／必须／禁止／违反后果**，一 folder 一文件，≤50 行；
- 无判据来源（真实运行记录、上游规范、可复现缺陷）的约束不入库。

## 变更边界

- 只可**加严**，不可放宽或删除；确需删除须双链辩论＋用户确认＋CHANGELOG 记账；
- 与其他约束冲突时**取更严者**，不做「择一丢弃」；
- 变更一律经 [../../update/update.md](../../update/update.md)
  （report→compare→release→clean）。

## 违反后果

红线被稀释后审查失去基准，测试链路问题无法归因，回退范围不可界定。
